## 7. MongoDB Configuration & Concurrency Verification

- **Local Standalone Deployment:** MongoDB connection established to `mongodb://localhost:27017/parking?retryWrites=false` with detected topology `Single`.
- **Transaction Detection Logic:** `supportsTransactions()` in `server/utils/transaction.js` detects the absence of replica sets (`setName` undefined, topology `Single`) and safely routes execution with `session = null`.
- **Compensation Rollback:** In `createLot` (lotController.js), if bulk slot insertion fails on standalone instances where multi-document transactions cannot rollback atomically, the server executes `ParkingLot.findByIdAndDelete(createdLot._id)` to guarantee database consistency.
- **Atomic Double-Booking Guard:** In `createReservation` (reservationController.js), slot reservation uses `Slot.findOneAndUpdate({ _id: slotId, lot: lotId, status: 'available' }, { $set: { status: 'reserved' } })`. Concurrent requests competing for the same slot receive `null` and are immediately rejected with `HTTP 409 Conflict`, mathematically eliminating double-booking without requiring replica-set locks.
